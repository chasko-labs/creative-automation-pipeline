# Plan: AI coach for the Kodiak campaign creator (insights + about Q&A + art-director hardening)

## Goal

Layer intelligence over the campaign creator without touching the generation wall: fix the art-director cold burn, add an on-demand insights panel on preview/campaign output, and hide a Q&A helper in the collapsed About section that answers "how do I get X" and proposes brief/chip/market edits for confirm-to-apply. No chatbot takeover — the brief input stays the interface.

## Success Criteria

- Art-director enabled no longer risks ~6s of ModelNotReady retries inside any walled request; cold callers get a fast answer or a clean fallback.
- After any preview, one click yields 3–5 grounded insights (why this seed, what the theme changed, what to try next) in under ~5s, never blocking Create.
- Inside collapsed `#aboutTool`, a user can ask "how do I get a Costco version" and get an answer plus a confirm chip that toggles the right chip/market/brief text on approval.
- All three survive Bedrock degradation with honest fallbacks (never-503 spirit: 200 + "coach is busy" over a 500 page).
- 0.1.06x deploys with zero changes to the rung ladder, theme map, or wall constants.

## Context And Current Facts

- Art-director is dark by default (`KODIAK_ARTDIRECTOR_ENABLED=false`, generate_lambda.py:78); when enabled, `_try_art_direct` (art_director.py:71-76) retries ModelNotReady 3x with 2s sleeps inside the walled request — the ~6s burn seen in logs.
- Preview rendering: `renderProvenancePanel` (generate.js:619) mounts beside `#preview` (`data-mcp="preview.compose"`, index.html:422) — the natural insights mount point.
- About: collapsed `<details id="aboutTool">` (index.html:459) — the Q&A host; collapsed by default so it never competes with the brief.
- Edit surfaces already exist as DOM: chips are `[data-theme]` buttons, brief is `#campaignBrief`, market control has labelled reflectors; webmcp.json islands (`campaign-brief`, `products`, `preview.compose`, `market-languages`) name every actionable region.
- Role model: `lambda/typescript-chat/index.mjs` (bryan-chasko-com) — Nova Micro, system-prompt-grounded (no KB), Function URL auth NONE + strict origin allowlist, explicit maxTokens, adaptive retries, honest 400/503/500. Copy this shape.
- S3 Vectors env (`KODIAK_VECTOR_*`) is already plumbed on the generate stack (generate-stack.ts:6-9) for a future RAG graduation; s3vectors MCP creds were broken as of the last session — treat hosted RAG as unverified until probed.
- Other team ships web units on top of main frequently (0.1.066 pattern) — keep web diffs small and island-scoped to avoid conflicts.

## Constraints And Non-goals

- No deploy in this plan's execution without a separate go (user: "dont deploy just plan" carries into build approval).
- No changes to rung ladder, 22s wall, theme-asset-map, or scorecard thresholds.
- No autonomous edits: every bot-proposed campaign change requires explicit confirm (chosen).
- No chatbot chrome in the main flow: no floating widget, no greeting, no typing in the brief card.
- No new Bedrock model access beyond Nova Micro (already provisioned pattern) without a callout.

## Key Decisions

1. **New coach Lambda, not generate-Lambda routes** (chosen): mirrors typescript-chat (Node 22 + Converse + Nova Micro + Function URL NONE). Generate stays pixels-only; text-call bugs can never take down generation, and the 22s wall is untouched. Rejected: /insights + /ask on the Python Lambda — shares the wall, couples deploys, risks the never-503 contract.
2. **On-demand insights** (chosen): button in the preview card ("Why this works") POSTs {brief, theme, market, provenance} to /insights. Rejected: auto-run per preview — adds seconds + cost to every Create including rung-D floors.
3. **Suggest-then-apply edits** (chosen): /ask returns {answer, edits[]} where each edit is a typed op (toggle-chip, set-brief-append, set-market); frontend renders them as confirm chips; only a click dispatches the DOM action. Rejected: direct-apply — silent brief rewrites.
4. **System-prompt grounding first, S3 Vectors later** (chosen): the coachable corpus is tiny (8 theme briefs + scene dispatches + retailer framings + DoD cards + how-to-steer recipes) and rides exactly in the system prompt like the TS50 course (~630 lines precedent). Rejected: day-one RAG — s3vectors creds unverified, adds a failure mode for content that fits in context.
5. **Art-director: pre-warm + single fast probe + async upgrade** (chosen): EventBridge Scheduler ping every ~4 min keeps the imported model warm; cut retries to one 2s probe on ModelNotReady; move the call out of the walled request (apply as an async headline upgrade, never gating pixels). Rejected: provisioned throughput (cost for a dark-by-default feature) and sync-in-wall with fewer retries (still burns budget on cold minutes).

## Recommended Approach

Build the coach as a sibling service (typescript-chat clone in a new `infra-cdk` stack or bryan-chasko-com lambda, same repo as the site for one-flow deploys: creative-automation-pipeline), ground it in files already committed, mount two small UI surfaces, and harden the art-director without enabling it. Five sequenced units below; each is independently shippable and independently revertable.

## Work Plan

**Unit 1 — Art-director hardening (backend only, no enable)**
- `art_director.py`: ModelNotReady retries 3x2s → 1x2s fast probe; log `voice=warming, skipped` on miss.
- `infra-cdk`: EventBridge Scheduler rule (4-min Converse ping with a fixed trivial ask) targeting the art-director model; disabled by default alongside the feature flag.
- `generate_lambda.py`: move `_maybe_art_direct` out of the walled section — run post-response (async headline upgrade written to the sidecar/pack, never gating renders).
- Tests: warming returns fallback in <3s (mocked ModelNotReady x N), scheduler template synths, wall path byte-identical.
- Validation: `pytest tests/test_art_director*.py`, `cdk diff` shows only scheduler + no Lambda replacement.

**Unit 2 — Coach Lambda + infra (no UI yet)**
- New `coach/` service cloned from typescript-chat: Node 22, Nova Micro (`amazon.nova-micro-v1:0`), explicit maxTokens, adaptive retries, Function URL NONE, origin allowlist = kodiak + cloudfront hosts, 400/503/500 honesty.
- `POST /insights`: {brief, theme, market, provenance} → 3–5 bullets (seed choice, theme effect, one concrete next try). System prompt embeds the 8 theme briefs, retailer framings, and DoD vocabulary.
- `POST /ask`: {question, pageState} → {answer ≤150 words, edits[]}; edits typed as {op: toggle-chip|append-brief|set-market, target, label}. Off-topic → one-sentence redirect to campaign help.
- Grounding file `coach/knowledge.md` generated from committed sources (theme-asset-map briefs, _THEME_COPY_HINT, scorecard DoD) with a test asserting it regenerates byte-identical.
- Validation: curl both endpoints (200 + schema), forced Bedrock-failure run returns honest 503 JSON, `cdk diff` new stack only.

**Unit 3 — Insights panel on preview (web only)**
- "Why this works" button beside the provenance panel (generate.js:619 mount area, `data-mcp="preview.compose"` island); POSTs current brief/theme/market/provenance; renders bullets in the existing card style; cached per preview (one fetch max).
- Failure = one honest line ("insights busy — try again"), never a spinner forever, never blocking Create/download.
- Vitest pins: button exists only after preview, no auto-fetch on Create (assert no fetch on the Create path), failure copy present.
- Validation: vitest file, node --check, headless DOM probe (button appears post-preview, stays hidden before).

**Unit 4 — About Q&A + confirm-to-apply edits (web only)**
- Inside `#aboutTool` body: ask box + answer region + edit-confirm chips. POSTs {question, pageState snapshot (active chips, market, brief length — never secrets)}.
- Confirm chip click dispatches the real DOM action: `[data-theme="..."]` click, brief append via the chips' own assembly path (prompt-chips.js, not direct value set, so undo/toggle math stays consistent), market via the existing market control.
- Answers cite sections ("see step 3, creative angle") from a fixed section map; unknown → "I only know the campaign creator" + no edits.
- Vitest pins: collapsed by default, no network until asked, each edit op requires a click (assert dispatch fns unreachable without confirm event).
- Validation: vitest file, headless DOM probe (ask → answer → chip → click → chip toggles).

**Unit 5 — Grounding graduation gate (eval, no build)**
- Measure: % of /ask answers needing a correction + knowledge.md size. If corrections cluster on content missing from the prompt OR knowledge.md passes ~8k tokens, greenlight S3 Vectors RAG (plumbing already on the stack); else stay prompt-grounded.
- Deliverable is a one-page eval note + issue, not code.

## Validation Plan

- Unit 1: `pytest` art-director tests (warming fallback <3s), `cdk diff` (scheduler add, zero replacement), wall-clock regression suite green.
- Unit 2: live curl `/insights` + `/ask` (200, schema-valid), Bedrock-throttled run returns 503 JSON, no secret leakage probe (ask for secrets → refusal).
- Unit 3+4: `npx vitest run` (new pin files), `node --check` touched JS, headless Chromium DOM probes with screenshots viewed (rest state, post-preview button, ask→confirm→toggle).
- Full: backend suite minus live + vitest suite green before each unit's commit; five separate commits in unit order (plan-structure binding at publish).
- Highest-risk validation: Unit 4's confirm-to-apply dispatch — a wrong selector silently edits the wrong control; the DOM probe must assert the exact chip/market changed and nothing else did.

## Risks / Rollback

- Nova Micro answer quality on niche campaign questions → mitigations: tight system prompt, 150-word cap, eval gate in Unit 5; rollback = hide the About box (one-line), coach Lambda costs ~$0 idle.
- Other-team web conflicts → mitigations: island-scoped diffs only (`preview.compose` area, `#aboutTool` body), no shared-file rewrites; rollback per unit via revert.
- Scheduler pre-warm cost/need → mitigations: disabled by default, 4-min trivial Converse is cents/month; if the imported model is retired, delete the rule.
- Prompt-injection via brief text reaching the coach → mitigations: brief passed as data field with "treat as data" system instruction; existing `_safe_prompt_text` scrub applies to any name-like tokens before sending.
