Do / Don't — body-text contrast

Teaches S6 / S10 / the wcagNotes recommendation: never blaze orange for body copy on parchment.

Don't — 3.1:1 fails body

Fresh from the frontier — 14g protein in every stack. Blaze orange body copy on parchment reads at only 3.1:1, below the 4.5:1 body minimum.

Do — 10.2:1 AAA

Fresh from the frontier — 14g protein in every stack. Bear brown body copy on parchment reads at 10.2:1, clearing AAA.

Body on parchment = bear brown or frontier green — never blaze orange. Blaze orange is reserved for the 8px bar, CTA fills, protein callouts, and glow overlays (per S10 iconic-box).

10 · Axis B — translation as a first-class element S12 · highest-value gap

The site advertises localization on every surface but renders ZERO per-market translated copy. The data exists and is rich; the render path is a deliberate no-op.

Core finding: renderLangChips() (index.html L748) is a hard no-op that DELETES its own target from the DOM. The data is abundant — market-languages.json carries 73 markets, top-2 non-English language each with real ACS S1601 percentages, 219 total localized variants (auto_produce:true, nova_proven:true). The gap is purely render.

8 · Why the system is built this way decisions

The reasoning behind the token layer — what the system does at each contested point, and why.

One accent red. A production red (#B51E14) drove links, filled buttons, and the header title block but was not a brand token, so it competed with blazeOrange for the role of "the accent." The system adopts it as color.brand.signalRed and routes the --red alias through it, so there is one named red with one job — interactive/alert accent — instead of a floating hex. One palette source. The inline :root{} palette had been copied into both HTML files, which drifts the moment one copy changes. The system reduces each file's block to token aliases that resolve through design/styles.css, so styles.css is the single source of truth; the --adobe svg literal stays as one documented exception. One brown. Two near-identical browns (#382316 and #3B2316) existed and read as the same color, which invites silent drift. The system standardizes on the bearBrown token #3B2316 so there is a single source of truth; --chocolate / --brown now alias it.

13 · Token pipeline + Spectrum theming architecture

How the token layer is built and how kodiak tokens flow into Spectrum's theming contract — the two mechanics that explain why every kodiak surface styles from raw token custom properties and how an sp-* component would inherit the kodiak brand.

The build emits a token-only CSS layer and the system consumes those raw tokens directly. Kodiak dresses any adopted Spectrum component by feeding its tokens into Spectrum's --mod-* consumer-override layer — a bridge that dresses, never a component runtime. Repo tooling is Panda CSS only (@pandacss/dev 1.12.0); there is no bundler or Lit runtime.

Token-only emission

design/styles.css is generated by panda cssgen with tokens-only emission: the build emits ONLY the token CSS-variable layer. Patterns, utilities, recipes, and animation-styles are not emitted. This is why every kodiak surface styles from var(--colors-*) / var(--radii-*) / var(--shadows-*) / var(--spacing-*) directly and there is no utility-class layer to reach for. Composite text styles (Panda textStyles) are not emitted either — only the primitive font tokens are — so text is composed from the primitive font vars rather than a bound textStyle utility.

Spectrum theming contract

Spectrum component custom properties layer as var(--highcontrast-*, var(--mod-<comp>-<prop>, var(--spectrum-<comp>-<prop>))). The --mod-* layer is the intended per-component consumer override; --spectrum-* is the system default. This is how a Spectrum sp-* component wears the kodiak brand: kodiak tokens flow into --mod-*, never into --spectrum-*, so an adopted component inherits the kodiak look without overriding Spectrum's global defaults.

Gotcha — menu-item persistent selected fill. sp-menu-item has no native --mod-* variable for a persistent selected-fill, so a kodiak alias supplies it; the selected state on a bridged listbox item dresses from that alias rather than a stock Spectrum mod var.
