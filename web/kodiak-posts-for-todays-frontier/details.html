Start here — what this page is reference

This page is the visual guide for a campaign that turns local seasonal ingredients into printable Kodiak recipe cards. Color, type, cards, and previews are described in plain language first; the live scorecards at the bottom check the same choices automatically. The recipe card itself — the printable keepsake — is specified under recipe card standard, with its field-by-field inventory in the template inventory just above it.

Terms, introduced once then shortened: Digital Asset Library (DAM) — the approved image store · artificial intelligence (AI) — the generation tools · Scalable Vector Graphics (SVG) — the placeholder sketches · stock-keeping unit (SKU) — the product catalog entry · call to action (CTA) — the create button · Web Content Accessibility Guidelines (WCAG) — the contrast rules.

How it works: generation steps are on pipeline: generation and localization; hosting is on infrastructure: hosting and delivery.

The logo default is input_assets/brand/logo.png (lockups enforced by brand-guard.js). The header bear crossfades to the alt logo past 40px scroll (js/scroll-swap.js); canvas covers use a bear placeholder when cover art is missing (js/data-core.js). Shared types live in js/globals.d.ts; the Spectrum token mapping is §12 of design-system-inventory.

Prototype defaults reference

The example opens with Park City, Utah and a nearby rural pairing so the campaign can demonstrate local context. A team can choose another market before creating a campaign.

Do / Don't — body-text contrast

Web Content Accessibility Guidelines (WCAG) guidance: use bear brown or frontier green for body copy on parchment.

Don't — 3.1:1 fails body

Fresh from the frontier — 14g protein in every stack. Blaze orange body copy on parchment reads at only 3.1:1, below the 4.5:1 body minimum.

Do — 10.2:1 AAA

Fresh from the frontier — 14g protein in every stack. Bear brown body copy on parchment reads at 10.2:1, clearing AAA.

Body on parchment uses bear brown or frontier green. Blaze orange stays reserved for the 8px bar, call-to-action fills, protein callouts, and glow overlays.

12 · Accessible control patterns reference

What Adobe Spectrum is, what we took from it, and how each control maps — in plain words. The short version: Spectrum is Adobe's free, open-source box of ready-made UI parts (buttons, dropdowns, menus) that already handle keyboard nav and screen readers correctly. We do not ship those parts — there is no component runtime in this app, just our own HTML dressed in kodiak tokens. What we took is the behavior contract: each of our controls works the way its Spectrum twin works, so anyone who later swaps in the corresponding part gets the same keyboard and screen-reader behavior for free.

Plain example. Our market picker is a plain list with role="option" rows. Spectrum's version of the same thing is called sp-picker: a button that opens a menu, arrow keys move, Enter picks, Escape closes, and a screen reader announces each choice. Our picker already does all of that by hand — if we ever drop in an sp-picker, the only job left is color: point its paint settings at our tokens and it looks kodiak. That paint step is the token bridge: our colors go in, the palette stays consistent.

Any focus ring on a bridged part resolves to the signalRed token (var(--colors-brand-signal-red)), rather than a raw hex.

8 · Why the interface works this way decisions

The reasoning behind the token layer — what the system does at each contested point, and why.

One accent red. A production red (#B51E14) drove links, filled buttons, and the header title block but was not a brand token, so it competed with blazeOrange for the role of "the accent." The system adopts it as color.brand.signalRed and routes the --red alias through it, so there is one named red with one job — interactive/alert accent — instead of a floating hex. One palette source. The inline :root{} palette had been copied into both HTML files, which drifts the moment one copy changes. The system reduces each file's block to token aliases that resolve through design/styles.css, so styles.css is the single source of truth; the --adobe svg literal stays as one documented exception. One brown. Two near-identical browns (#382316 and #3B2316) existed and read as the same color, which invites silent drift. The system standardizes on the bearBrown token #3B2316 so there is a single source of truth; --chocolate / --brown now alias it.
