CDK stacks live

Single canonical app, adopted in place (#122). Six stacks.

  • generate-stack — GenerateLambda (brief-to-hero handler) behind a public dev-open Function URL the site calls directly; Bedrock grants for Nova Pro, Stability control-structure + outpaint, Nova embed + Titan fallback.
  • data-stack — DynamoDB localization-memory + retail-network (pay-per-request); S3 pipeline-log + style-library buckets (TLS-only policy).
  • bedrock-logging-stack — cross-region Bedrock invocation logging + X-Ray tracing (#122).
  • observability-stack — pipeline observer spans, scorecard + compliance gates (#42).
  • browser-observability-stack — RUM + CloudFront log bucket for the live frontend.
  • hosting-stack — S3 frontier-bryanchasko-com + CloudFront E3GEX8LSRX6OYS + kodiak.bryanchasko.com alias, adopted in place (#202, all RETAIN). Origin access control provisioned, not yet attached. Content still ships via scripts/deploy-frontier.sh, never via CDK.
  • Example — generate-stack Lambda — GenerateLambda, container image, memorySize 3008, timeout 300, public Function URL (AuthType NONE) the site POSTs /generate to; Bedrock grants cover Nova Pro, Stability control-structure + outpaint, and Nova multimodal embeddings with Titan fallback (amazon.nova-2-multimodal-embeddings-v1:0).

Database schemas live

Every store the pipeline reads or writes, with key layout and a real row.

  • DynamoDB kodiak-creatives-localization-memory — pay-per-request, PITR on, RETAIN on delete. Single-table keys: pk = MARKET#<market> (HASH), sk = LANG#<lang>#MSG#<sha1-16> (RANGE) — built by localize_memory.build_key. The /localize path checks it before calling Translate, so repeat captions cost a read, not a translation.
  • Example row — pk MARKET#US-W-SPOKANE / sk LANG#en#MSG#782a7f241acbbb92 → text "Spokane Falls to the ponderosa pines — protein-packed whole grains for your Spokane frontier", provider precomputed, source dynamodb (live scan 2026-09-08).
  • DynamoDB kodiak-creatives-retail-network — pay-per-request, RETAIN. Key: store_id (HASH) + GSI byMarket on market (projection ALL) for market→stores lookup. Example: 0 items as of 2026-09-08 — store discovery not yet ingested, so the API falls back to the curated JSONL.
  • S3 Vectors kodiak-vectors / index kodiak-assets — multimodal embeddings, 1024 dims, cosine distance, float32 (Nova multimodal default; Titan embed fallback). Powers "riff on past content" similarity over past DAM renders. RETAIN on delete.
  • S3 DAM chasko-creative-dam-946179428633-us-east-1 — versioned, KMS SSE + bucket-key, full public-access block, TLS-only policy, RETAIN. Layout under brands/kodiak/: renders/ (per-campaign packs, e.g. renders/output_kodiak-costco/), renders/restyle-cache/ (content-addressed restyled seeds — under renders/ because the Lambda role grants Put/Get only on renders/* and library/*), raw-ingest/ (source photos, e.g. raw-ingest/kodiakcakes/images/705599011627_FlapjackMix_Buttermilk_Front_1.png), plus heroes/ logos/ recipes/ references/ tokens/ vectors/.
  • S3 pipeline-log + style-library buckets — kodiak-creatives-logs-946179428633-us-east-1 (pipeline observer spans) and the DAM style-library bucket (TLS-only, RETAIN, MPU-abort 7d + renders tiering lifecycle).

Market + localization data live

Where "in season here" and translated copy actually come from — files, schemas, and seams.

  • places[] inline table live — js/data-core.js, 73 markets, one object per line: {market, place, retailer, zip, audience, message, peppers, cheeses, cue}. No endpoint — ships inside the JS bundle. Feeds the headline default, brief YAML, chooser hints, and the in-season fallback chain: artisanal copy → places message/cue → generic-only-if-unknown.
  • Example — US-MW-PARKCITY-84098 → "Park City, Utah 84098", message "Keep It Wild — protein-packed whole grains for your Wasatch frontier. Nourishment for Today's Frontier", cue "Farmers Market at Park City Mountain Resort Wed 11–5 — Jensen Farms peaches, Copper Moose rhubarb, Tagges preserves…".
  • market-languages.json live — data/localization/market-languages.json, 74 markets built from store-finder-markets.json + US Census ACS 5yr Table S1601. Entry: {market, place, zip, top_languages: [{lang_code, lang_name, pct, reason, translate_code, pct_home}]} — the machine_translate flag the frontend checks today lives in the JS inline fallback, not in this file. Delivery is two-tier: inline fallback object in data-core.js (works file:// offline), upgraded at runtime by fetching data/localization/market-languages.json from the site bucket. Consumers: marketLangsFor(), lang chips, tile captions.
  • Example — Park City top_languages[0]: es / Spanish / 5.8% ("ACS 2023 5yr Summit County…"), translate_code es.
  • local-flavor.json (month-aware produce) staged — data/localization/local-flavor.json, schema local-flavor-v1: 6 markets + _default, each {place, source, produce: [{name, months[1-12], peak}]}, reader src/creative_automation/local_flavor.py (local_flavor_for(market, month), tested). Honest status: UNWIRED on both sides — no JS reads it, no Python caller imports it. The UI still uses the 5-entry JS flavorMap plus the places fallback. Wire it before quoting it.
  • Example — Pescadero: Castroville artichokes months [3,4,5,6] peak 4; Marin goat cheese [2,3,4,5,6]. Default row covers all 12 months with "seasonal frontier flavor".
  • POST /localize live — generate_lambda._handle_localize → localize_service.localize(text, market, target_lang) returns {text, source, provider, lang}. Order: English passthrough → precomputed/DynamoDB memory hit → ethics guard (Navajo nv + Zapotec zip return unchanged, never machine-translated) → Translate. Frontend localizeText() posts {text, market, target_lang} to window.KODIAK_LOCALIZE_ENDPOINT ('/localize' on hosted, null offline). Full-mode server-side localization is emptied — frontend owns copy.

Edge + ship path live

How pixels reach the browser and how code reaches the pixels.

  • Static edge — S3 frontier-bryanchasko-com + CloudFront, live at kodiak.bryanchasko.com. scripts/deploy-frontier.sh syncs the 8 top-level files + asset dirs and invalidates; it refuses on version drift.
  • Version stamp — scripts/bump-version.sh sweeps every version-shaped sink mechanically (meta, title, manifest, stamps).
  • CI — CodeBuild everywhere (no GitHub Actions); local pre-push gate replaces the trigger (#129).
  • DAM origin — S3 chasko-creative-dam-946179428633-us-east-1, renders under brands/kodiak/renders/, served presigned.
  • Example — ship + verify — ./scripts/bump-version.sh 0.1.035 && ./scripts/deploy-frontier.sh then read back: curl -s https://kodiak.bryanchasko.com/index.html | grep -o "build 0.1.035-[0-9a-f]*-[0-9]*" must print the stamp whose SHA is the merged HEAD — the deploy is not done until the read-back matches.

Deploy runbook

How to ship the stacks and the edge from a clean checkout — every command copy-paste-verified against the repo, no aspirational boxes (#176).

  • Prereqs — SSO login on profile bryanchasko-kiro (account 946179428633): aws sts get-caller-identity --profile bryanchasko-kiro --region us-east-1 must succeed. Node 22+ with npm (CDK 2.1140.0 pinned in infra-cdk/ devDependencies — run npm install there first). CDK bootstrap once per account+region: npx cdk bootstrap aws://946179428633/us-east-1 --profile bryanchasko-kiro and the same for us-west-2 (the second Bedrock-logging instance lives there).
  • Container image first — GenerateStack references a pre-built image (kodiak-creatives-generate:latest); build + push BEFORE deploying it: aws ecr get-login-password --region us-east-1 --profile bryanchasko-kiro | docker login --username AWS --password-stdin 946179428633.dkr.ecr.us-east-1.amazonaws.com, then docker build --provenance=false --sbom=false -f infra/generate.Dockerfile -t kodiak-creatives-generate:latest . from the repo root, tag + push. The two flags are load-bearing: stock docker buildx emits an OCI image index, which Lambda rejects — without them the function update fails even though the push succeeds.
  • Synth + deploy, in order — from infra-cdk/: npm run synth, then npx cdk deploy kodiak-creatives --profile bryanchasko-kiro (data — import first if live, never plain-deploy over the live bucket/tables), kodiak-creatives-observability, kodiak-creatives-generate -c generateEcrRepo=kodiak-creatives-generate -c generateImageTag=latest (after the ECR push), KodiakCreativesBedrockLoggingUsEast1, KodiakCreativesBedrockLoggingUsWest2, kodiak-creatives-browser-observability. Live-resource import (zero-destroy, all RETAIN): npx cdk import kodiak-creatives --profile bryanchasko-kiro with physical ids DAM bucket chasko-creative-dam-946179428633-us-east-1, tables kodiak-creatives-localization-memory + kodiak-creatives-retail-network; same pattern for /kodiak/creative-pipeline and /aws/bedrock/kodiak-model-invocations. Fresh environment: skip import, deploy directly.
  • Frontend ship — ./scripts/bump-version.sh [semver] && ./scripts/deploy-frontier.sh. Deploy refuses on version drift (content changed without a bump) — recovery is running the bump, never editing around it; deploy never auto-bumps. Dry run first: DRY_RUN=1 ./scripts/deploy-frontier.sh.
  • Verify — backend: POST a preview brief to the FunctionUrl deploy output and confirm {"ok":true} + a rung source label (see pipeline Run it). Edge: read back the stamp — curl -s https://kodiak.bryanchasko.com/index.html | grep -o "build <semver>-[0-9a-f]*-[0-9]*" must print the just-shipped stamp — then wait ~3 min of edge settle after the invalidation before calling a mismatch real: CloudFront serves stale edge copies until the /* invalidation completes, so an immediate read-back miss is settle, not failure; re-check after 3 min and only then investigate.
  • Rollback — failed cdk deploy rolls the stack back automatically (CloudFormation default) — read the failure event, fix, npx cdk diff, re-deploy; never force-delete a RETAIN stateful resource (DAM bucket, tables, log groups). Frontend has no S3 versioning — rollback is re-shipping the last-good tree: check out the last-good commit's web/kodiak-posts-for-todays-frontier/, bump, deploy, verify read-back.
  • Local pre-push gate (#129) — one-time scripts/hooks/install.sh per clone; per push the hook runs ruff lint; before opening/merging the PR run the full gate scripts/hooks/full-check.sh (vitest → panda/kodiak parity → chromium spectrum + render-baseline → pytest + cfn-lint + nova-act smoke). Full procedure: docs/ci-local-gate.md.

Testing + proof runbook

How the pipeline proves itself before anything ships — tiers, enforced contracts, and where the evidence lives. Test counts as of 2026-09-08: 65 pytest modules, 20 vitest pin files.

  • Gate tiers — per push: ruff lint only (hook, ~1s — a heavy per-push gate gets skipped into uselessness). Before merge: scripts/hooks/full-check.sh, six gates in order: vitest (token CSS, no browser) → panda/kodiak parity → chromium spectrum-a11y → chromium render-baseline → full pytest + cfn-lint + nova-act live smoke. Full procedure: docs/ci-local-gate.md.
  • Contracts enforced by tests, not by promise — never-503 (a well-formed POST always returns 200 real pixels), the wall-clock ladder budget, the honesty rule (#203: every scorecard either runs a real pixel/config test or is marked unscored and excluded — no placeholder subs, no unconditional passes), retired-slug removal (removed angles never resurface in the map), and the theme-photo fast path (a spy test fails if a theme seed ever triggers a Nova vision call).
  • Path audit + adversary — tests/test_path_audit.py runs every shipped theme through the real ladder once and scores shared DoD cards (four ratios at exact dims, real DAM seed, theme-photo path taken, explicit scene dispatch, copy sidecar, honest provenance, no celebrity token) plus path-specific cards — 100% to pass, JSON scorecard to /tmp/path-audit-scorecard.json. tests/test_path_adversary.py attacks with unknown themes, empty briefs, typed celebrity names, captive-bear briefs, author crashes, and prompt injection. The audit has caught real gaps (retailer chips with no map entries; an author exception escaping at the call site).
  • Image scorecards — src/creative_automation/scorecards.py (brutal 12 cards, 100% threshold — one failed subcheck fails the image; Pillow histograms + regex, no generative leniency). Run: CLI scorecards command writes scorecards.json per batch.
  • Proof on every render — each preview carries its provenance (source rung, seed selection, scene prompt) in the How-this-was-made panel and the copy sidecar — the receipt is part of the output, not a separate claim. Deploys are receipted the same way: stamp read-back on the edge (see Edge + ship path), live render checks against production URLs, lesson issues filed on the repo (e.g. runbook + #276 for the 403 arc).
